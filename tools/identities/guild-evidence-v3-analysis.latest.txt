## C. Current Guild-V2 Pipeline
1. Current and historical guild observations are grouped by physical guild identifier.
2. V2 selects the latest historical observation before the earliest post-fusion guild timestamp and current F28 observations.
3. High-confidence Player identities build old-member -> new-member flow edges.
4. Identity candidates are created when exact name, same CoA, or sufficiently large mutual-dominant member flow exists.
5. Other member flows remain memberMigrationEdges.
6. split/convergence are derived from old/new top-flow conflicts.
7. autoEligible requires exact name + same CoA + mutual dominant flow + at least 3 matched players + no assignment conflict.
8. Management ready is currently equivalent to one active autoEligible guild identity; otherwise active identity candidates become review.
9. Management does recompute after reservation cleanup, but it only promotes candidates whose existing `ready` flag is true. For guilds, that flag is still the strict V2 autoEligible predicate, not a V3 evidence classification.

## S. Circular Evidence Guard
Pass 1 should resolve Player identities from independent player evidence only. Pass 2 may use Ready/Completed players as guild evidence. Pass 3 may confirm Guild identities. A later optional Player refinement pass may use confirmed Guild identity, but those refined players must not be fed back into the same Guild pass.

## T. Guild Resolver V3 Specification
1. Model guild evidence as ordinal entries: neutral, weakSupport, support, strongSupport, anchor, warning.
2. Build identity candidates only from direct identity evidence; keep migration edges separate.
3. Classify candidates as rejected, weak, plausible, strong, anchored.
4. Apply one-to-one historical reservation after classification, not before evidence is visible.
5. Recompute final status from the final candidate pool: Ready for exactly one assignment-free strong/anchored candidate; Review for multiple/actionable conflict; Unresolved when historical data exists but no actionable identity remains; No Historical Data only when coverage is absent.
6. Keep leader/officer continuity optional and non-blocking until coverage is demonstrably reliable.
7. Treat first post-fusion observations as primary identity evidence and later observations as migration/rename/context evidence.
