## B. Current evidence families and proposed hard separation
- Origin: reliable mismatch remains hardContradiction; resolved match is eligibility/weakSupport rather than identity evidence.
- Class: mismatch remains hardContradiction; same class is eligibility/weakSupport.
- Level monotonicity: regression remains hardContradiction; monotonic alone is weakSupport at most.
- Level progression: normal/plausible-burst/extreme are plausibility modifiers, not identity anchors.
- Base attributes: monotonicity is separate from unchanged-stat/fingerprint evidence.
- Fortress/Pets: availability-aware continuity evidence; missing is neutral.
- Logical guild continuity: availability-aware support signal; missing/unresolved is neutral.
- Exact name / fusion base name / name history: direct identity anchors when not contradicted.
- Assignment/reservation: global conflict control, not per-candidate support evidence.

## G. Ordinal evidence calibration draft
| Evidence family | Proposed ordinal category | Rationale |
| --- | --- | --- |
| Class mismatch / reliable origin mismatch / reliable level regression / individual base-stat regression | hardContradiction | Already product hard rejects and should stay outside support weighting. |
| Exact name / fusion base name | identityAnchor | Direct identity signal; still subject to hard contradictions and assignment conflicts. |
| 3+ unchanged base stats, especially secondary stats | strongSupport candidate | More specific than monotonicity; keep empirical guard because false collisions still exist. |
| Same confirmed logical guild | support candidate | Useful reducer, but F2PKrümel still has a same-guild collision set. |
| Fortress continuity | support/strongSupport candidate when available | Often decisive for semantic-ready cases, but unavailable must stay neutral. |
| Pet continuity | weakSupport/support candidate | Helpful but can collide across hard false controls. |
| Base monotonicity | neutral eligibility / weakSupport only in combination | Too broad; all difficult false controls pass. |
| Base ordering / simple ratios | diagnostic weakSupport | Needs combination with unchanged stats or guild; not an anchor alone. |
| Level monotonicity | neutral eligibility | All difficult false controls pass; hard only on regression. |
| Normal level progression | support modifier | Can break ties in current product logic, but not an identity anchor. |
| Plausible burst | neutral/weakSupport | Acceptable but less selective than normal progression. |
| Extreme positive progression | weakContradiction unless protected by identityAnchor/strong semantic evidence | Current warning/cleanup role is supported conceptually. |

## H. Resolver architecture recommendation
1. Keep hardContradictions as an independent gate before any positive evidence hierarchy.
2. Represent evidence as named ordinal chips, not additive numeric weights.
3. Split baseAttributesConsistent into baseMonotonicity plus fingerprint features: unchanged count, unchanged secondary stats, ordering, and small ratio checks.
4. Treat missing guild/fortress/pets as neutral, never negative.
5. Let assignment/reservation stay as global conflict handling after candidate evidence classification.
6. Validate any future Ready rule against both positive controls and this review false-control pool before enabling it.
